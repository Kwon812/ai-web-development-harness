# Workflow Harness

## 목적
개발을 Phase와 기능 단위로 나누고 계획·구현·검증·보고·승인 순서를 유지한다.

## 기본 흐름
요구사항 분석 → 서비스 기획 → 기술·아키텍처 승인 → UI/UX 설계 → Phase 계획 승인 → 기능별 구현 → 테스트 → 보고 → 사용자 승인 → 다음 기능 → Phase 종합 보고 → Phase 승인.

## 진행 조건
- 현재 작업 단위와 수용 기준이 정의되어 있어야 한다.
- 선행 결정이 승인되어야 한다.
- 한 번에 하나의 기능 단위만 구현한다.
- 기능 보고서가 작성되고 승인되어야 다음 기능으로 이동한다.

## 중단 조건
요구사항 충돌, 데이터 손실 위험, 보안 문제, 승인되지 않은 설계 변경, 테스트 실패가 해결되지 않은 경우 진행을 중단하고 보고한다.
