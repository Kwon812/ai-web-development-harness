# Workflow Harness

## 목적
개발을 Phase와 기능 단위로 나누고 계획·구현·검증·보고·승인 순서를 유지한다.

## 기본 흐름
요구사항 분석 → 통합 서비스 기획(기능·UI/UX 방향·아키텍처·기술 스택·Phase 계획 제안) → 기획안 통합 승인 → 상세 설계 및 기능별 구현 → 테스트 → 보고 → 사용자 승인 → 다음 기능 → Phase 종합 보고 → Phase 승인. 기술 스택 결정만을 위한 별도 단계·승인을 만들지 않는다.

## 단계별 산출물
- 분석 완료: `reports/analysis-report.md`
- 통합 기획 및 승인: `reports/planning-report.md`
- 각 Phase 기능별 구현·테스트·승인 및 Phase 종합 결과: `reports/phases/phase-NN-report.md`
- 모든 산출물은 실제 `.md` 파일로 작성·갱신한다. 터미널 출력만으로 완료하지 않는다.

## 진행 조건
- 현재 작업 단위와 수용 기준이 정의되어 있어야 한다.
- 선행 결정이 승인되어야 한다.
- 한 번에 하나의 기능 단위만 구현한다.
- 해당 Phase의 Markdown 보고서에 기능별 결과가 기록되고 승인되어야 다음 기능으로 이동한다.

## 중단 조건
요구사항 충돌, 데이터 손실 위험, 보안 문제, 승인되지 않은 설계 변경, 테스트 실패가 해결되지 않은 경우 진행을 중단하고 보고한다.
