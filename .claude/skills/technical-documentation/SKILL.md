# Technical Documentation

## 절차
1. 구현 범위와 실제 변경 사항을 확인한다.
2. 요구사항 및 설계 근거와 구현 결과를 연결한다.
3. 테스트 실행 결과와 미실행 사유를 기록한다.
4. 특이사항, 미해결 문제, 사용자 확인 사항을 정리한다.
5. `docs/REPORT-TEMPLATE.md` 형식으로 보고서를 작성한다.
6. 프로젝트 상태와 결정 로그를 갱신한다.

## 규칙
실제 근거가 있는 내용만 기록한다. 추정은 추정으로 표시한다. 사용자 승인 전 다음 작업을 진행하지 않는다.
