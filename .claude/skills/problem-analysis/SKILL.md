# Problem Analysis

## 목표
해결해야 할 문제를 명확히 정의하고 검증 가능한 요구사항의 출발점을 만든다.

## 절차
1. 사용자 요청에서 문제, 원하는 변화, 대상 사용자를 추출한다.
2. 사실, 가정, 미확인 정보를 구분한다.
3. 현재 대안과 불편, 문제 발생 맥락을 정리한다.
4. 기능·비기능 요구사항 후보와 제약사항을 도출한다.
5. 성공 기준과 측정 방법을 제안한다.
6. 불명확하거나 결정이 필요한 질문을 우선순위와 함께 제시한다.

## 산출물
- 문제 정의
- 목표 및 비목표
- 사용자와 사용 맥락
- 요구사항 후보
- 제약·가정·위험
- 확인 질문과 성공 기준

## 규칙
근거 없는 사용자 요구를 사실로 단정하지 않는다. 기술 구현안을 문제 정의보다 먼저 확정하지 않는다.
