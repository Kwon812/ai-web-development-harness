# Service Planning

## 절차
1. 문제 정의와 사용자 조사 결과를 확인한다.
2. 서비스 목표, 대상 사용자, 핵심 가치를 정리한다.
3. 사용자 시나리오와 핵심 사용자 흐름을 작성한다.
4. 기능을 Must/Should/Could 등으로 우선순위화한다.
5. MVP 범위와 제외 범위를 명시한다.
6. 기능별 수용 기준과 비기능 요구사항을 작성한다.
7. 기술 스택 및 시스템 아키텍처(프론트엔드, 백엔드, DB, 인증, 배포, 데이터 흐름)를 요구사항에 맞춰 비교·제안한다. 필요하면 technology-selection Skill을 내부적으로 활용하되 별도 선정 단계로 분리하지 않는다.
8. 기능을 Phase와 작업 단위로 나누고 의존성, 검증 기준, 위험과 확인 질문을 정리한다.
9. 기능 범위·아키텍처·기술 스택·Phase 계획을 하나의 기획안으로 제출해 통합 승인받는다.

## 산출물
서비스 개요, 사용자 유형, 기능 명세, 사용자 흐름, MVP 범위, 수용 기준, 기술 스택 비교·추천, 시스템 아키텍처, Phase 계획, 위험 목록.

## 규칙
아이디어와 확정 요구사항을 구분한다. 사용자 승인 전 범위를 확정하거나 구현으로 넘어가지 않는다.
