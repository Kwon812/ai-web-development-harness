# Technical Documentation

## 절차
1. 실제 변경 파일과 구현 범위를 확인한다.
2. 요구사항, 담당자 답변, 설계 근거와 구현 결과를 연결한다.
3. 실제 테스트 결과와 미실행 사유를 기록한다.
4. 다음 항목을 포함하는 보고서를 해당 Phase의 Markdown 파일에 저장한다. 대화 출력만으로 완료 처리하지 않는다.

## 기능 구현 보고서 필수 항목
1. 작업 개요: Phase, 기능명, 구현 목적
2. 구현 범위: 구현 내용과 제외한 내용
3. 구현 방식: 기술, 구조, 로직, 선택 이유
4. 구현 근거: 요구사항, 담당자 답변, 설계 판단
5. 변경 파일: 생성·수정 파일과 내용
6. 테스트 결과: 정적 검사, Unit, Integration, E2E, 실제 브라우저 UI, 회귀 테스트별 실행 명령·케이스·PASS/FAIL/NOT RUN/NOT APPLICABLE 및 근거. 브라우저 검증 시 화면 크기와 UI 확인 내용도 기록
7. 특이사항: 오류, 제약, 미해결 문제
8. 사용자 확인 사항: 확인이 필요한 사실·검토 항목과 근거
9. 사용자 판단 필요 사항: 선택지, 추천안·근거, 구현 영향, 결정 상태
10. 다음 작업: 다음 기능 및 선행 조건
11. 승인 상태: PENDING / APPROVED / CHANGES_REQUESTED / BLOCKED

모든 공통 항목은 해당 사항이 없더라도 제목을 유지하고 `없음`을 명시한다.

## Phase 종합 보고
완료 기능, 통합 테스트 결과, 잔여 위험, 미해결 사항, 다음 Phase와 승인 요청을 해당 Phase 보고서에 기록한다.

## 규칙
실행하지 않은 검사를 통과로 기록하지 않는다. 보고 후 명시적 승인 전에는 다음 기능으로 넘어가지 않는다. 각 Phase의 Markdown 보고서는 반드시 생성하거나 갱신한다.
