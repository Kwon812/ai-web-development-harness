# Testing QA

## 절차
1. 요구사항·담당자 답변·수용 기준을 확인하고 기능별 테스트 계획을 수립한다.
2. 정상, 경계, 예외, 권한, 보안 시나리오를 포함한다.
3. 정적 검사(타입·린트·빌드), Unit, Integration, E2E, 실제 브라우저 UI, 회귀 테스트의 적용 여부를 각각 판단한다.
4. 해당 기능에 적용 가능한 테스트를 실제 실행하고 명령, 케이스, 결과를 수집한다.
5. Unit으로 함수·검증·변환·비즈니스 로직을, Integration으로 API·DB·인증 등 연동을 확인한다.
6. Phase 종료 전 핵심 사용자 흐름을 E2E로 검증하고, 가능한 경우 실제 브라우저에서 렌더링·클릭·입력·이동·콘솔 오류·반응형 화면을 확인한다. E2E 성공과 UI 확인을 동일시하지 않는다.
7. 실패 시 재현 조건, 원인, 영향 범위를 분석하고 수정 후 관련 테스트 및 회귀 테스트를 다시 실행한다.
8. 각 계층을 PASS / FAIL / NOT RUN / NOT APPLICABLE로 분류하고 실제 근거를 Phase 보고서에 저장한다.

## 산출물
테스트 계획, 계층별 테스트 케이스·실행 명령·실제 결과, 브라우저 확인 기록, 결함·잔여 위험을 해당 `reports/phases/phase-NN-report.md`에 누적 기록한다.

## 규칙
- 테스트 미실행을 PASS로 표시하지 않는다.
- NOT RUN에는 환경 제약과 대체 검증 및 위험을, NOT APPLICABLE에는 적용 제외 근거를 적는다.
- 핵심 E2E·브라우저 검증이 불가능하면 임의로 성공 처리하지 않고 사용자 판단 필요 사항에 포함한다.
- 외부 서비스, 테스트 데이터, 브라우저 설치가 필요한 경우 승인·보안 규칙을 따른다.
